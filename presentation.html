Risk Assessment

Top 5 Risks & Mitigations

Honest assessment. Every risk has a mitigation plan.

Architecture restructure breaks existing imports

Impact: High • Likelihood: Medium

Mitigation: Re-export pattern preserves all existing imports. Every import like from antigravity_engine import X continues to work. Verified with import smoke tests before each merge.

Architecture migration takes longer than estimated

Impact: High • Likelihood: Medium

Mitigation: Phased approach: typing pass (2 days) → dead code removal (2 days) → package structure (2 days) → decomposition (4 days). Each phase is independently verifiable.

Golden baseline drifts due to non-deterministic AI behavior

Impact: Medium • Likelihood: High

Mitigation: Fixed random seeds in all experiments. Configurable drift threshold (2%) instead of hardcoded. Weekly baseline verification.

Dead code removal deletes useful but unused code

Impact: Medium • Likelihood: Low

Mitigation: Conservative approach: only remove code confirmed unused by static analysis (ruff F401) plus manual review by module owners.

Pre-commit hooks annoy contributors

Impact: Low • Likelihood: Medium

Mitigation: Start in advisory-only mode (warnings, not blocks). Enforce in CI later. Developers can bypass with --no-verify if needed.

Speaker Notes

‘Let me be transparent about the risks.’

‘The biggest risk is the architecture restructure. We’re moving 140 files from a flat layout into a package structure. But we’re not breaking anything: every existing import statement keeps working through a re-export pattern. It’s the same as rearranging books in a library without changing the ISBN catalog.’

‘The second biggest risk is the timeline. The architecture work is 10-14 days, which is the longest single phase. But we’ve broken it into 4 sub-phases so we can measure progress at each step.’

‘The golden baseline drift risk is interesting: AI systems are inherently non-deterministic. Our mitigation is fixed random seeds in all experiments and a configurable 2% drift threshold. If the AI changes by less than 2%, we consider it normal variation.

‘Low-risk items like pre-commit hooks: we start in advisory mode. Developers get warnings but aren’t blocked. This avoids the ‘this tool is annoying’ problem that kills adoption of good practices.’

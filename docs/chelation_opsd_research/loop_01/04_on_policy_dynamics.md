## Executive Summary

The CHELATEDAI chelation system attempts **self-correction of embedding representations** via lightweight residual adapters (`x + δ(x) + normalize`) trained through **sedimentation cycles** (historical collapse replay) and **micro online updates** (inference-time contrastive steps). 

**Core Finding**: The current training regime is **predominantly off-policy with sparse, thresholded signals**, mixed with a limited **micro on-policy component** (OnlineUpdater). This creates exactly the pathologies that modern On-Policy Self-Distillation (OPSD / SDPO / MIS-PO) techniques were engineered to solve: distribution shift, poor credit assignment, high gradient variance, catastrophic forgetting during reinforcement of self-edits, and abysmal sample efficiency.

**Key Mismatch**:
- Sedimentation = classic offline replay RL (collapse logs under old policy → batch Adam/ES updates). Sparse reward (collapse frequency >= threshold).
- Self-healing directives = advisory proposals for "adapter_sft", "online_contrastive_update", "eggroll_es" — but execution rarely closes a true on-policy self-distillation loop.
- OnlineUpdater = the *only* true on-policy element (current-policy retrievals provide positives/negatives for InfoNCE/triplet micro-steps), but it is micro, optional, and lacks the privileged-teacher asymmetric + KL control machinery of OPSD/SDPO.

**OPSD/SDPO Transfer Opportunity**: Enormous. By re-framing chelation corrections as **on-policy self-distillation of residual deltas** (student adapter on normal context vs. teacher adapter on privileged diagnostics/context), using **dense per-"token" (per-query or per-dimension) divergence objectives**, **filtered sampling (MIS-PO style)**, and **explicit KL / deviation clipping from identity/reference**, we can turn advisory SelfEditDirectives into stable, sample-efficient, persistent adapter improvements without destroying base retrieval knowledge.

This report maps every dynamic in detail, identifies 7 concrete upgrade pattern families with variances for testing, and provides practical training-loop pseudocode and integration points for Loops 2–10.

## 1. Fundamental Differences: On-Policy vs Off-Policy in Self-Correction / Self-Editing Systems

### 1.1 Classical Definitions (Adapted to Representation Correction)

- **Off-Policy Training**: The data (queries, "trajectories", or collapse events) used for the gradient update was generated by a *previous* version of the policy (adapter). The update improves the *current* policy but the behavior that produced the data no longer matches the learner. Classic example: DQN replay buffer, or CHELATEDAI's `chelation_log` + `run_sedimentation_cycle()`.

- **On-Policy Training**: The data is generated *by the current policy being updated* (or a very recent snapshot). Gradients reflect the actual distribution the model will encounter at inference. Example: PPO/GRPO rollouts, or the existing `OnlineUpdater.update(query, top_k, bottom_k)` where top/bottom are produced by the adapter *right now*.

In **self-correction / self-editing** (the CHELATEDAI + SEAL/EGGROLL goal):
- The "policy" is the composition of base embedder + ChelationAdapter (or Procrustes/LowRank/AttnRes variant).
- A "trajectory" is a query → retrieval ranking → diagnostic signals (structural_health, collapse count, retention probes).
- A "correction" is the learned δ (residual) that improves future retrievals.
- Self-edits (SelfEditDirective) propose *which* correction strategy + synthetic data to reinforce.

**Critical Dynamic Differences** (with evidence from repo):

| Aspect                  | Off-Policy (Current Sedimentation Dominant) | On-Policy (Ideal OPSD-Style) | Impact on Chelation Stability/Efficiency |
|-------------------------|---------------------------------------------|------------------------------|------------------------------------------|
| Data Distribution      | Historical collapses (old adapter + old corpus state) | Fresh queries sampled from *current* adapter | Off-policy → covariate shift → adapter "chases" stale problems, causes oscillation or forgetting |
| Reward / Supervision   | Sparse scalar (collapse count >= threshold) + synthetic homeostatic target | Dense per-query (or per-dimension) signal from teacher policy on same rollout | Sparse → high variance gradients, credit assignment failure (which part of adapter caused collapse?) |
| Credit Assignment      | Whole vector MSE/InfoNCE on target; all dimensions updated uniformly | Token-level (query-level) divergence; only "regret" tokens/dimensions get strong signal | Poor assignment → adapter over-corrects safe dimensions, under-corrects critical ones |
| KL / Deviation Control | Implicit via near-id init + Procrustes reg + BoundedAdapter | Explicit per-step KL(p_teacher || p_student) + pointwise clipping + reference policy penalty | Missing → "KL shocks" (large sudden deltas) destroy base knowledge (documented in panel reviews F-ML-xxx) |
| Sample Efficiency      | High: needs many historical collapses before threshold triggers training | Medium-High: 1 rollout per query suffices if teacher provides dense soft targets | Current system wastes massive inference-time data; only trains on rare "frequent collapsers" |
| Forgetting Risk        | High (repeated offline passes on same old data drift the adapter) | Lower (on-policy keeps adapter honest to current inference distribution + KL anchors) | Core pain point in task_plan.md, findings.md, self_healing_chelation "retention_replay_guard" |
| Exploration vs Exploitation | Relies on noise_injection + ES population diversity | Natural from current policy sampling + filtered acceptance | ES already partially on-policy (population around current params); can be hybridized |

### 1.2 Why Self-Correction Magnifies the Problem

Self-editing systems (SEAL, ReST^EM, STaR, OPSD) generate their own training data from the model. Without on-policy discipline + filtering + KL control:
- Bad corrections (from weak diagnostics) get reinforced → model collapse.
- Good corrections are drowned in noise or never reinforced persistently (advisory mode).
- The "self" in self-edit becomes inconsistent: directive generated under policy π_t, but trained under offline replay of π_{t-k}.

OPSD explicitly solves this by **sampling from student (current), distilling from teacher (privileged same-model copy)** on that exact rollout.

## 2. How OPSD Techniques Handle On-Policy Data Collection, Filtering, and Reinforcement

### 2.1 OPSD (Self-Distilled Reasoner, arXiv:2601.18734)

**Core Loop** (paraphrased + mapped):
1. **Student samples on-policy trajectory** ŷ ~ p_S(· | x)   [in CHELATEDAI: current adapter(embed(query)) produces retrieval ranking + diagnostics]
2. **Both student and teacher evaluate the *same* prefix/trajectory**:
   - p_S(next | x, ŷ_<n)   [normal context / normal diagnostics]
   - p_T(next | x, y*, ŷ_<n)   [privileged context: ground-truth y* or rich feedback]
3. **Minimize per-token (per-position) divergence** D(p_T || p_S) averaged over the rollout. Gradients **only through student**.
4. **Stabilizers**:
   - Fix teacher as initial policy snapshot (regularization).
   - **Per-token pointwise KL clipping** (prevents stylistic/high-KL tokens from dominating; analogous to per-dimension or per-sample delta clipping).
   - JSD / forward+reverse KL hybrids for stability.
5. **Result**: RL-like performance ceiling + distillation-like sample efficiency (1 rollout vs GRPO's 8–16). No external teacher model required.

**Privileged Information in OPSD**: Verified solution y*. The model is capable enough to "rationalize" why y* is correct even when it couldn't generate it.

### 2.2 SDPO (Reinforcement Learning via Self-Distillation, arXiv:2601.20802)

Extends the idea to **rich textual feedback** environments (compiler errors, judge comments, runtime traces) instead of only ground-truth answers.
- Sample rollout (attempt).
- Obtain tokenized feedback f.
- Re-condition the *same model* on (prompt + f) → self-teacher produces corrected next-token distribution.
- Distill back (KL or similar) into policy.
- Works even in pure scalar-reward settings by using *successful* rollouts as implicit feedback for failed ones.
- Test-time self-distillation accelerates discovery (same pass@k with 3× fewer attempts).
- Gains increase with scale (better in-context retrospection).

### 2.3 MIS-PO / Filtered Sampling Stabilizers

From 2026 Step reports (e.g., 2602.10604):
- Instead of continuous importance sampling ratios (PPO), use **discrete filtering**: discard trajectories whose importance ratio or divergence from reference exceeds threshold.
- Accepted samples treated as "effectively on-policy".
- Dramatically lowers gradient variance/spikes, improves stability for long-horizon reasoning.
- Directly applicable to SelfEditDirective acceptance: only reinforce directives whose post-edit fitness/retention/quantization gate + structural_health pass a strict filter.

**Common Pattern Across All**: On-policy rollouts + privileged/self-teacher context → dense soft targets → divergence loss + aggressive filtering/clipping + reference anchoring.

## 3. Precise Mapping to Current CHELATEDAI SelfEditDirective + ChelationAdapter Dynamics

### 3.1 Self-Healing Chelation Planner (self_healing_chelation.py)

**Generation** (`generate_directives`):
- Takes `context` + `diagnostics` (runtime anomalies, structural_health, quantization_gate, retrieval_policy).
- Emits `SelfEditDirective` with `adaptation_mode` ("adapter_sft", "online_contrastive_update", "eggroll_es", "quantization_gate", "structural_health_penalty", "retention_replay") + `optimization_params` + synthetic_examples.
- **This is already a primitive "teacher context" generator**: diagnostics are privileged signals.

**Evaluation** (`evaluate_directives`, `execute_shadow_round`):
- Sandboxed fitness via `FitnessFunctionInterface`.
- Gates: reward > threshold, retention_score >= 0.8, quantization_gate passed, structural_health.
- Ledger records provenance.
- **But**: `allow_persistent_update` defaults to False; "base_model_mutation_allowed": False. Plans are mostly advisory. Actual reinforcement is *not* performed here.

**Gap vs OPSD**:
- No actual on-policy *sampling* of a "trajectory" under the directive's proposed adapter.
- No teacher/student split on the *same* generated data using the directive's own synthetic_examples or diagnostics as privileged.
- No dense divergence loss; just scalar fitness gate then (later) MSE/InfoNCE or ES.

### 3.2 Sedimentation Cycle (antigravity_engine.py:run_sedimentation_cycle + sedimentation_loss.py)

**Data Collection (Inference Phase)**:
- During `embed()` / `_gravity_sensor` / retrieval: `self.chelation_log[id].append(noise_vector)` for "bad" interactions.
- Purely observational, under whatever current adapter is loaded.
- **Off-policy by design** once sleep cycle runs (adapter may have been updated multiple times).

**Target Computation**:
- Baseline: `compute_homeostatic_target(current, noise_list, push_mag)` — average noise, push away. Synthetic, sparse.
- Offline/hybrid: `teacher_helper.generate_distillation_targets(texts, current_embs, teacher_weight)` — external or ensemble teacher (not self).
- Then Adam or eggroll_es on (input_array, target_array) with MSE or InfoNCE (batch contrastive treating paired target[i] as sole positive).

**Training Loop Dynamics**:
- Full batch epochs (default 10) on *only the collapsers* (threshold=3).
- Regularization only via adapter.regularization_loss() (Procrustes skew Frobenius; others 0) + optional noise_injection + Kalman LR + convergence_monitor.
- After update: sync new adapted vectors back to Qdrant.
- **Major Dynamics Issues** (mapped from audit + code):
  - High variance if few collapsers.
  - When all targets "good" or "bad", no signal (analogous to GRPO all-correct batch).
  - Distribution shift: targets derived from old policy's failures.
  - No per-sample filtering beyond frequency threshold.
  - No KL term anchoring outputs to pre-update adapter (only implicit near-id init which decays over cycles).
  - ES path (eggroll) is population-based derivative-free around current params — partially "on-policy" in parameter space but still uses off-policy targets.

### 3.3 OnlineUpdater (online_updater.py) — The Hidden On-Policy Gem

This is the **closest existing implementation to OPSD principles** in the repo:

- Triggered per-query (or every N via `update_interval`).
- `update(query_vec, top_k_vecs, bottom_k_vecs, ...)` — top/bottom produced by *current* adapter's retrieval ranking → **on-policy data**.
- Adapter forward on query/pos/neg → pluggable loss (TripletMarginOnlineLoss, InfoNCEOnlineLoss, CosineSimilarityOnlineLoss) → 1–few micro SGD steps (micro_steps=1 default, tiny LR=1e-4).
- Supports AdaptiveMargin, OnlineLossScheduler, OnlineUpdateDiagnostics (gradient stats).
- Enabled via `enable_online_updates()` in engine.

**Strengths (OPSD-like)**:
- Truly on-policy (current policy defines positives/negatives).
- Dense contrastive signal per query.
- Low overhead, continual.

**Weaknesses vs Full OPSD/SDPO**:
- No privileged teacher context (no diagnostics or "correct retrieval" conditioning).
- No asymmetric student/teacher split on same rollout.
- No explicit KL / deviation-from-reference penalty (only grad clip + momentum).
- Only contrastive on retrieval results; no use of SelfEditDirective synthetic_examples or full self-healing loop.
- Very conservative (micro) → may never accumulate enough signal for hard self-edits.
- Not integrated with sedimentation or directive ledger.

**Huge Leverage Point**: The OnlineUpdater can be the **execution engine** for "online_contrastive_update" directives from self-healing, upgraded with teacher diagnostics.

### 3.4 Other Relevant Dynamics

- **Evolution Strategies (evolution_strategies_optimizer.py + eggroll_es in sedimentation)**: Population sampling around current adapter params, fitness evaluation (retrieval + structural + quantization). Antithetic, elite, kalman_sigma, fitness shaping. This is on-policy in *parameter space* (perturbations of live policy). Can be viewed as derivative-free OPSD analog.
- **BoundedAdapter + min/max_correction**: Attempts to keep deltas above INT8 noise floor (~0.0078) and below divergence threshold. Primitive magnitude clipping (cf. OPSD pointwise KL clip).
- **Procrustes (Orthogonal + DSM)**: Hard constraint (Cayley) + learned per-dim scale. Strong inductive bias for "small rotation" corrections — excellent substrate for KL-style regularization (the reg_loss on skew already penalizes large A).
- **Stability / retention machinery** (stability_tracker.py, quantization_promotion_gate.py, fitness_interfaces.py): Already compute retention_score, fp32 vs quantized fitness, structural_health, isomer detection. These are perfect "privileged signals" for a teacher policy.

## 4. Identified Upgrade Patterns & Method Variances (For Testing in Subsequent Loops)

Based on the dynamics analysis, here are **7 high-leverage pattern families** with concrete variances to implement/test. Each maps directly to OPSD/SDPO/MIS-PO + current code gaps. All preserve the residual near-identity philosophy.

### Pattern Family 1: On-Policy Sedimentation (Replace/Reinforce Offline Replay)
**Core Idea**: During/after inference batches, treat recent queries as on-policy rollouts. Use current adapter + fresh diagnostics to generate targets on the fly instead of historical chelation_log.

**Variants to Test**:
- **1A (Pure On-Policy Rollout)**: Sample N live or replayed queries with current adapter → compute retrievals/diagnostics → generate privileged targets (e.g. via model_scope or self-generated "ideal" via retention probes) → InfoNCE + KL(adapted || base) loss. Train only on this fresh batch. (No threshold; always use recent data.)
- **1B (Hybrid Replay + Fresh)**: Maintain a small on-policy buffer (last K queries) + old collapses; sample mixed with higher weight on fresh. Use MIS-PO filter: only include rollouts where post-adapter fitness gain > τ and retention > 0.85.
- **1C (Directive-Guided On-Policy)**: For accepted SelfEditDirective with "online_contrastive_update", run a dedicated on-policy micro-cycle using the directive's synthetic_examples as privileged context.

**Implementation Points**:
- Modify `run_sedimentation_cycle` to accept an `on_policy_mode=True` flag.
- New helper in `sedimentation_trainer.py`: `collect_on_policy_batch(engine, num_queries=32, use_diagnostics=True)`.
- Add `OnPolicyBuffer` class (circular, stores (query_text, current_emb, topk_ids, diagnostics_dict)).

**Expected Dynamics Win**: Eliminates distribution shift; dense signal per recent query; better sample efficiency (no waiting for 3+ collapses).

### Pattern Family 2: Asymmetric Privileged-Context Distillation for Adapters
**Core Idea**: Make the adapter "see" diagnostics as extra conditioning for teacher path only (asymmetric).

**How** (since adapters are simple vec→vec):
- Embed diagnostics (structural_health score, collapse flags, quantization_gate dict → small MLP or hash to vector) → concat or add to input embedding for teacher forward only.
- Or: two forward passes — student: adapter(x); teacher: adapter_with_privileged(x, diag_embed) where we temporarily augment the correction_net input dim or use a cross-attn variant.
- Loss: ||teacher_out - student_out||^2 + contrastive or full divergence on the pair + reg.

**Variants**:
- **2A (Diagnostic Concat)**: Extend ChelationAdapter (and others via factory) to accept optional `diag_context` vector. Teacher path uses it.
- **2B (Separate Teacher Head)**: Keep base adapter for student; a parallel small "teacher_adapter" (or same weights + diag projection) only for distillation targets.
- **2C (LayerAttentionAggregator + Diagnostics)**: Use existing LayerAttentionAggregator but inject diagnostic embeddings as an extra "layer".

**Integration with Self-Healing**: When `adaptation_mode="adapter_sft"` or similar, the `diagnostics` passed to planner become the privileged context for the teacher during the subsequent training step.

**OPSD Mapping**: Exactly the student (x only) vs teacher (x + y*/privileged) split. Here y* = rich diagnostics + self-generated probes.

### Pattern Family 3: Explicit KL / Divergence Regularized Residual Training + Clipping
**Core Idea**: Add OPSD-style KL control directly to the adapter loss to prevent "KL shocks" and forgetting.

**Loss Sketch** (new in sedimentation_loss.py or dedicated `chelation_distillation_loss.py`):
```python
# student_out = adapter(x)   # normal
# ref_out = no_grad(adapter_ref(x)) or x (identity) or previous snapshot
# teacher_out = privileged_teacher(x, diag)
kl_term = 0.5 * (F.kl_div(..., log_target=True) or mse(student_out, ref_out) + beta * mse(student_out, teacher_out))
# Per-"dimension" or per-sample clipping
delta = student_out - x_norm
clipped_delta = torch.clamp(delta, -max_delta, max_delta)  # or pointwise on norm
loss = contrastive(student_out, targets) + lambda_kl * kl_term
```

**Variants**:
- **3A (Reference KL to Identity)**: Always penalize deviation from input (or frozen copy of adapter at start of cycle). Matches Procrustes philosophy.
- **3B (Per-Dimension Pointwise Clip)**: Analog to OPSD per-token clip. Compute |delta_i| contribution to loss; cap high-KL (high delta) dimensions.
- **3C (JSD Hybrid + Reverse KL)**: Use generalized JSD (beta tunable) between teacher/student + reverse KL to reference to prevent mode collapse.
- **3D (Adaptive KL Weight)**: Use kalman or loss-variance to schedule lambda_kl (prevent over-regularization early, strong anchoring late).

**Existing Hooks**: BoundedAdapter already does magnitude rescaling; extend it with KL term. Procrustes reg_loss already does something similar (penalize large skew).

### Pattern Family 4: Filtered + MIS-PO-Style Self-Edit Reinforcement
**Core Idea**: Turn the SelfEditEvaluation / ledger into a filter before any persistent training. Only "on-policy-good" directives get reinforced.

**Variants**:
- **4A (Hard Filter Pre-Training)**: In `build_update_plan` or new `execute_persistent_reinforcement`, only accepted directives where `reward > 0.05 AND retention >= 0.9 AND quant_pass AND structural > 0.75` proceed to actual adapter update. Discard others (like MIS-PO discard high-ratio samples).
- **4B (Soft Reweighting)**: Use fitness/reward as importance weight or advantage in the loss (analog GRPO advantage).
- **4C (Group Self-Edit)**: For one context, generate 4–8 directives (population), evaluate all, keep only the elite 2 for distillation (eggroll_es already does population; unify with self-healing).
- **4D (Test-Time Self-Distillation)**: For hard queries, apply SDPO-style repeated micro self-distill using environment feedback (retrieval success/failure) before final answer. (Leverage existing OnlineUpdater + directives.)

**Implementation**: New method `SelfHealingChelationPlanner.execute_filtered_reinforcement(...)` that calls engine's training only on filtered set. Update `allow_persistent_update` default behavior.

### Pattern Family 5: Dense Contrastive Self-Distillation on Synthetic + On-Policy Mix
**Current InfoNCE** in sedimentation_loss and OnlineUpdater is already dense batch contrastive.
**Upgrade**: Make positives/negatives richer using self-generated probes + privileged teacher outputs.

**Variants**:
- **5A (Multi-Positive from Probes)**: For a directive's synthetic_examples + self_generated_eval_probes, encode multiple "correct" views (with/without diag context) as positives for the student output.
- **5B (Hard Negative Mining + Directive)**: Use existing HardNegativeMiner + add "bad" synthetic from rejected directives.
- **5C (Cross-Directive Distillation)**: Distill between two accepted directives' adapters (ensemble teacher).

### Pattern Family 6: Hybrid Online + Sedimentation with Shared On-Policy Buffer + Scheduler
**Variants**:
- **6A (Micro-Online Accumulation)**: OnlineUpdater writes successful micro-updates into a small buffer; sedimentation pulls from it for larger batch consolidation (with KL anchoring).
- **6B (Dual Optimizer Schedule)**: Use Online (SGD micro, high frequency) for fast local correction; sedimentation (Adam/ES, lower frequency) for global consolidation with stronger reg.
- **6C (Loss Scheduler Unified)**: Extend OnlineLossScheduler + new SedimentationLossScheduler + teacher_weight_scheduler into one `ChelationOPSDScheduler` that also controls KL weight, filter thresholds, privileged context strength.

### Pattern Family 7: Quantization-Aware + Low-Rank On-Policy Variants (Eggroll + OPSD)
**Variants**:
- **7A (ES + On-Policy Targets)**: Modify `train_adapter_with_es` to use fresh on-policy inputs + privileged teacher fitness instead of static targets.
- **7B (Bounded + KL-Aware ES)**: During population eval, penalize individuals whose delta norm or KL-to-ref exceeds bounds (quant survival baked into fitness).
- **7C (LowRank + Asymmetric)**: For LowRankAffineAdapter, apply the U/V factors differently in teacher vs student path.

**All Patterns Preserve**: Near-identity init, normalization, save/load, factory, regularization_loss hook.

## 5. Practical Training Loop Implications & Recommended Architecture Changes

### 5.1 Recommended Master Training Loop Sketch (for Loop 3+ Implementation)

```python
# In antigravity_engine.py or new opsd_chelation_trainer.py
def run_opsd_chelation_cycle(self, queries_batch, diagnostics_batch, directives=None):
    # 1. On-policy collection under current adapter (student)
    student_embs = [self.adapter(self.embed(q)) for q in queries_batch]
    retrievals, diags = self._run_retrieval_with_diagnostics(queries_batch)
    
    # 2. Privileged teacher context (from directives + diagnostics + probes)
    teacher_context = self._build_privileged_context(diagnostics_batch, directives)
    teacher_embs = [self._teacher_forward(q, ctx) for q, ctx in zip(...) ]  # or same adapter + concat
    
    # 3. Filter (MIS-PO style)
    good_indices = [i for i in range(len(queries)) 
                    if retention_probe(teacher_embs[i]) > 0.85 and quant_gate_pass(diags[i])]
    if not good_indices: return
    
    # 4. Dense divergence loss (OPSD style) + existing contrastive
    loss = 0
    for i in good_indices:
        # Per-query (analog per-token) clipped KL / JSD / MSE(teacher, student) + InfoNCE
        div = clipped_kl_or_jsd(teacher_embs[i], student_embs[i], clip=0.05)
        loss += div + self.criterion(student_embs[i], homeostatic_or_probe_target[i])
    loss += 0.01 * self.adapter.regularization_loss()
    
    # 5. Update (with reference anchoring)
    loss.backward(); optimizer.step()
    # Optional: EMA update of teacher snapshot
```

### 5.3 Metrics for Dynamics Evaluation (Feed into Agent 6 Test Harness)

- **Distribution Shift**: KL or MMD between embedding distribution of training batch (sedimentation inputs) vs live inference queries.
- **Forgetting / Retention Delta**: Pre vs post update NDCG / recall on held-out probes (self-generated + BEIR).
- **KL Shock / Delta Magnitude**: Histogram of ||adapter(x) - x|| and max per-dim delta per update; track spikes.
- **Gradient Variance / Credit Assignment**: Per-layer / per-dim gradient norms during adapter backward; entropy of attention in BlockAttnRes during training.
- **Sample Efficiency**: Wall-clock tokens/queries or epochs to reach +X% retention_gain or fitness.
- **Filter Efficiency**: % of SelfEditDirectives that survive MIS-PO-style filter vs total generated.
- **Quantization Survival Post-Update**: fp32 vs int8 fitness delta after OPSD update.
- **Policy Improvement Rate**: OnlineUpdater success rate (loss decreasing + retrieval gain) over micro-steps.

## 6. Risks, Trade-offs, and Open Questions for Later Loops

**Risks**:
- **Teacher Quality**: If the "privileged" diagnostics/context is weak or leaking future info, teacher provides bad supervision → worse than baseline (mitigate with strict gates + frozen initial teacher snapshot).
- **Compute Overhead**: Asymmetric teacher forward + extra diagnostics embedding per query. Mitigate with small diag embed dim + caching.
- **Over-Filtering**: Too strict MIS-PO filter starves the learner of updates (monitor acceptance rate; have fallback curriculum).
- **Adapter Capacity**: Simple MLP/Procrustes may not have enough expressivity for rich privileged conditioning (consider upgrading BlockAttnRes or adding small cross-attn for diag in later variants).
- **Quantization Interaction**: Clipping/KL terms may push corrections below INT8 noise floor; BoundedAdapter must be co-designed.
- **Non-Stationarity**: On-policy buffer + continual micro-updates can cause rapid policy change; need stronger EMA teacher or periodic consolidation.

**Trade-offs**:
- On-policy purity vs practicality: Full live on-policy requires query traffic; offline on-policy buffer is safer for low-traffic deployments.
- Dense vs sparse: Full-vocab-style divergence on embeddings (contrastive over large negative banks) is richer but more expensive than simple MSE.
- Scale: Benefits of self-distillation grow with base model capability (diagnostics quality + rationalization power); test on multiple embedding backends.

**Open Questions for Loop 4 (Stability/KL) & Loop 5 (Filtering)**:
- Best divergence for continuous embedding space? (JSD, reverse KL, squared MMD, or contrastive InfoNCE with teacher as extra positives?)
- Optimal privileged context representation for diagnostics (scalar scores, one-hot flags, learned projection of full health report)?
- How to handle "no privileged signal available" cases gracefully (degrade to current homeostatic + online)?
- Interaction with model_scope / AEP orchestrator for richer privileged signals?

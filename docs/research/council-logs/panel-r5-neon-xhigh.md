## 2. Algorithmic & Methodological Scrutiny of `EM-4` (`M4f` / `M4g` / `C4_v4`)

Inspecting [em4_soft_telemetry_routing.py](file:///D:/GITHUB/CHELATEDAI-STAGE0-NIGHT1/em4_soft_telemetry_routing.py), [ek5_v3_stratified.py:1369-1555](file:///D:/GITHUB/CHELATEDAI-STAGE0-NIGHT1/ek5_v3_stratified.py#L1369-L1555), and [run_r5b_spark6724_completion.py:50-140](file:///D:/GITHUB/CHELATEDAI-STAGE0-NIGHT1/scripts/run_r5b_spark6724_completion.py#L50-L140) reveals six concrete engineering/methodological weaknesses that **must be disclosed**:

1. **Benchmark-Specific Regex Overfitting (`_EXTENDED_RECAP_RE` ↔ `_LME_ECHO_PREFIXES`):**
   - [em4_soft_telemetry_routing.py:46-58](file:///D:/GITHUB/CHELATEDAI-STAGE0-NIGHT1/em4_soft_telemetry_routing.py#L46-L58) hardcodes **all 6 exact synthetic echo prefixes** from `_LME_ECHO_PREFIXES` ([run_overnight_r5_spark6724.py:82-89](file:///D:/GITHUB/CHELATEDAI-STAGE0-NIGHT1/scripts/run_overnight_r5_spark6724.py#L82-L89)) character-for-character (`session recap note`, `memory summary log`, `background context carried forward`, `follow-up note recalling earlier detail`, `periodic assistant digest`, `stored profile reminder`).
   - Direct execution confirms why `M4e` collapsed to `0.5128` (`+0.00 pp` vs `M1`) on `LME-78` while `M4f`/`M4g` jumped to `0.7436`/`0.7564`: without those 6 hardcoded regexes, `classify_high_similarity_pair` returns `PRESERVE_CONFLICT (CONFLICT_PROPER_ENTITY)` on **5/6** `LME` prefixes (`Memory`, `Background`, `Follow-up`, `Periodic`, `Stored` are treated as proper nouns!).
   - On unseen natural recap wrappers (e.g., `"As you mentioned earlier, ..."`, `"Recapping what you shared: ..."`), `em4_soft_telemetry_routing.py` returns `is_recap_framed=False` and **`PRESERVE_CONFLICT (CONFLICT_PROPER_ENTITY)`**—proving `M4f`/`M4g`'s `LME-78` echo collapse does **not** generalize to arbitrary unseen natural-language recap phrasing without replacing regex stripping with a semantic/NLI detector. (Even on prefix #1, `_EXTENDED_RECAP_RE` stops at `:`, leaking `"user mentioned — "` into the stripped body.)
2. **Inverted Boolean Bug in Cluster Representative Selection ([em4_soft_telemetry_routing.py:226-234](file:///D:/GITHUB/CHELATEDAI-STAGE0-NIGHT1/em4_soft_telemetry_routing.py#L226-L234)):**
   - The sort key `1 if (recap_flags[m] and (top_m_hyb - float(hyb[cand_indices[m]])) < 0.08) else 0` is **inverted** relative to its comment (`"Prefer non-recap member if within 0.08 hybrid score of top cluster member; otherwise highest hybrid"`). Verified via minimal unit reproduction: on an all-recap cluster `[r1(hyb=0.50), r2(hyb=0.00)]`, `route_soft_telemetry_top_k` selects **`r2` (`hyb=0.00`) over `r1` (`hyb=0.50`)** because `0.50 - 0.00 >= 0.08` gives `r2` key `0` while `r1` gets key `1`! Similarly, in a mixed cluster, a low-scoring non-recap turn (`hyb=0.05`) beats a high-scoring recap (`hyb=0.90`).
3. **`M4f` Clean Zero-Regression Is Mostly Non-Activation + Uncalibrated Constants:**
   - Verified via `prompt_sha256` equality against `M1_hybrid_flat`: `M4f` emitted the **byte-identical prompt** to `M1` on **`297/300` (99.0%)** `LoCoMo-300` clean queries and **`487/500` (97.4%)** `LongMemEval-S N=500` clean queries (`0` accuracy diffs on either). (Also dead no-op loop at [em4_soft_telemetry_routing.py:296-298](file:///D:/GITHUB/CHELATEDAI-STAGE0-NIGHT1/em4_soft_telemetry_routing.py#L296-L298).)
4. **Transitive Single-Linkage Union-Find Drift ([em4_soft_telemetry_routing.py:189-211](file:///D:/GITHUB/CHELATEDAI-STAGE0-NIGHT1/em4_soft_telemetry_routing.py#L189-L211)):**
   - Clustering echoes by single-linkage Union-Find allows chaining (`A~B`, `B~C` where `A` and `C` diverge) to collapse `C` into `A` and erroneously back-date `C`'s `origin_ts` to `min(ts)`. Complete-linkage or medoid-anchored clustering avoids this.
5. **`C4_v4` Edge-Case Failure Modes ([run_r5b_spark6724_completion.py:50-140](file:///D:/GITHUB/CHELATEDAI-STAGE0-NIGHT1/scripts/run_r5b_spark6724_completion.py#L50-L140)):**

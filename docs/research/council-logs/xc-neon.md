### 2.1 Four Breaking Edge Cases in Carbon's Two-Axis `REFUTE` vs. `SUPERSEDE` Proposal ([r0-carbon.md:72-74](/D:/GITHUB/CHELATEDAI-STAGE0-NIGHT1/docs/research/council-logs/r0-carbon.md:72-74))
Carbon correctly discovered `F2-NEW-1` (Zombie Reinstatement on 2-step `SUPERSEDE`), **but Carbon's proposed 2-stage fix breaks on four realistic multi-agent graph topologies** (all verified in Python above):
1. **Repo's own `REFUTE + SUPERSEDE` pattern re-introduces Zombie Reinstatement (`Case D`):** In [run_flagship2_unified_zero_shortcut_and_locomo.py:179-180](/D:/GITHUB/CHELATEDAI-STAGE0-NIGHT1/scripts/run_flagship2_unified_zero_shortcut_and_locomo.py:179-180), corrections emit *both* `REFUTE` and `SUPERSEDE`. 2. **`CONTESTED` Superseder (`Case B`):** If $e_2 \leftrightarrow_{\text{REF}} e_x$ (so $e_2 = \texttt{CONTESTED}$) and $e_2 \xrightarrow{\text{SUP}} e_1$, Carbon's rule (*"only `VALID` nodes exert `SUPERSEDE` force"*) leaves stale **`e1 = ADMIT`**! In 3-valued epistemic logic, an unresolved superseder makes $e_1$'s currency unknown $\implies$ $e_1$ MUST be **`CONTESTED`**, not `ADMIT`.
3. **`SUPERSEDE` Cycles (`Case A`):** Under distributed clock skew / concurrent agent writes ($e_1 \xleftrightarrow{\text{SUP}} e_2$), Stage 1 marks both `VALID`, and Stage 2 marks **both `AUDIT_ONLY(SUPERSEDED)`** — silently erasing every record in the slot instead of surfacing `CONTESTED` abstention!
4. **Derived Copies of Superseded Nodes (`Case C`) & Self-Amending Patches:** Carbon's Stage 2 never propagates `SUPERSEDED` along `COPY_OF`/`DERIVES_FROM`, leaving stale summary $d_1 \xrightarrow{\text{COPY\_OF}} e_1$ as **`ADMIT`**! Conversely, naively propagating `SUPERSEDED` along all `DERIVES_FROM` breaks incremental patches ($e_2 \xrightarrow{\text{DERIVES\_FROM} + \text{SUPERSEDE}} e_1$) by making $e_2$ supersede itself!

### 2.2 Cyclic-Graph Unsoundness of Naive Counter-Gated Skipping (Carbon `F2-NEW-3` & **Self-Correction #1 to Neon R0**)
Both Carbon ([r0-carbon.md:89](/D:/GITHUB/CHELATEDAI-STAGE0-NIGHT1/docs/research/council-logs/r0-carbon.md:89)) and Neon ([r0-neon.md:67](/D:/GITHUB/CHELATEDAI-STAGE0-NIGHT1/docs/research/council-logs/r0-neon.md:67)) claimed that counter-gating lets us skip `add(src, dst, REFUTE)` in $O(1)$ whenever `src` is `REFUTED` (`AUDIT_ONLY`) and skip `del(r1, hub, REFUTE)` whenever another `VALID` refuter remains. **Exhaustive fuzzing refuted BOTH naive rules on cyclic graphs:**
- **Insert bug (`4/256` 2-node, `364/4,096` 3-node mismatches):** Insert `A --REFUTE--> B` (`A=VALID, B=REFUTED`), then insert `B --REFUTE--> A`. Because `B` is `REFUTED`, counter-gating skips `A` and outputs `{A: VALID, B: REFUTED}` instead of `{A: CONTESTED, B: CONTESTED}` — because `B` was only refuted *by `A`*!
- **Shielded-delete bug (`2/9,981` random ops):** With `X --REFUTE--> n0`, `n0 --REFUTE--> n5`, `n5 --REFUTE--> n0`, both `X` and `n5` are `VALID` so `cnt_valid_ref[n0]=2`. Deleting `X -> n0` leaves `cnt_valid_ref[n0]=1` (from `n5`), so naive counter-gating skips `n0`, missing that `n5` was only `VALID` because `X` refuted `n0`!
- **Exact theorem (verified `0/29,352` ops in §3.1):** Adding `(src, dst, REFUTE)` to an already-`REFUTED` `dst` IS unconditionally an $O(1)$ no-op (since $\Gamma_{P'}(T^*) = \Gamma_P(T^*) = U_{\text{poss}}$); adding from `REFUTED` `src` to non-`REFUTED` `dst` is a no-op iff backward reachability from `src` avoids `dst`; deleting `(src, dst, REFUTE)` is a no-op iff `dst` retains a `VALID` attacker or `REFUTED` dep whose backward cone avoids `dst` ($O(1)$ for root refuters!).

### 2.3 Two Mathematical Errors in Carbon's Proposition 1b ([r0-carbon.md:174](/D:/GITHUB/CHELATEDAI-STAGE0-NIGHT1/docs/research/council-logs/r0-carbon.md:174))

## Defect evidence and commands

`run_full_cycle()` accepts absent remediation and verification callbacks. The default flow records successful phase receipts, advances the untouched finding to `VERIFIED`, and returns a verified closure count even though no repair commit or verification evidence exists.

Expected current evidence: the probe reports `status: VERIFIED`, blank commit/evidence, four passing verification records, and `closure_verified: 1`. Existing tests pass because they permit the default no-callback progression rather than requiring a material repair receipt.

## Root cause and atomic fix steps

Phase completion is modeled as successful method return, not as a typed proof that remediation and independent verification occurred.

1. Define explicit no-callback semantics: analysis-only cycles must stop before remediation and can never emit `VERIFIED`.
2. Require a typed remediation receipt containing immutable candidate identity and changed-scope evidence before the status can leave remediation.
3. Require a separate typed verification receipt tied to that candidate before `VERIFIED`; reject blank or mismatched evidence.
4. Add no-callback, missing-receipt, mismatched-candidate, failed-verifier, and valid-receipt transition tests.

## Acceptance criteria

- **AC1:** the exact no-callback probe cannot produce a `VERIFIED` finding or verified closure count.
- **AC2:** blank, malformed, or candidate-mismatched receipts fail closed with an explicit incomplete/blocked state.
- **AC3:** only a distinct verification receipt for the exact remediation candidate can transition the finding to `VERIFIED`.

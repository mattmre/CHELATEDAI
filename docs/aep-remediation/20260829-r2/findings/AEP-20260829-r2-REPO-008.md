## Defect evidence and commands

The repository contains two dashboard clients. The inline client implements Phase C, Model Scope, and TTS panels with corresponding API handlers. The checked-in static client contains none of those panels, and `serve_dashboard()` always serves that static file when it exists. The richer components are therefore reachable only after the canonical file is missing.

```powershell
rg -n 'phase-c|model.scope|tts-|/api/phase_c|/api/model_scope|/api/tts' dashboard/index.html
if ($LASTEXITCODE -eq 1) { 'NO_STATIC_MATCHES' }
rg -n 'phase-c|model.scope|tts-|/api/phase_c|/api/model_scope|/api/tts' dashboard_server.py
rg -n 'serve_dashboard|serve_inline_dashboard|get_inline_dashboard_html' test_dashboard_server.py
if ($LASTEXITCODE -eq 1) { 'NO_PAGE_SELECTION_TESTS' }
python -m unittest test_dashboard_server -v
```

Expected current evidence: no static-client matches; multiple inline/handler matches; no test that asserts which page is served. The dashboard module ran 67 tests and returned `OK (skipped=2)`, but that suite exercises loaders/handlers rather than the served page composition.

## Root cause and atomic fix steps

Two independently evolved clients share one server contract, while file existence—not an explicit product decision—selects the less complete client.

1. Choose and document one canonical dashboard surface and deprecate the other; do not continue dual feature ownership.
2. If the static client remains canonical, port Phase C, Model Scope, and TTS as complete components with their loading/empty/error states before removing the inline copies.
3. If the inline client becomes canonical, make selection explicit and remove the static-first branch after equivalent regression coverage.
4. Add a real served-page smoke test that asserts every advertised panel and its endpoint wiring from the normal checkout.

- **AC3:** a served-page test fails if a supported panel or its request wiring disappears from the canonical surface.

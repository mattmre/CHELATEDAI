## Defect evidence

The child catches callback execution, but `conn.send(("ok", result))` occurs outside that try. An unpicklable result kills the child and deprives the parent of the causal serialization error. Exact head and [review thread](https://github.com/mattmre/CHELATEDAI/pull/257#discussion_r3367630945) were opened.

Copy-paste inspection:

```powershell
git show 663be66:aep_orchestrator.py | Select-String -Pattern "conn.send|callback\(finding\)|except Exception" -Context 8,10
gh api repos/mattmre/CHELATEDAI/pulls/comments/3367630945 --jq '[.path,.line,.body]'
```

Expected current evidence: callback execution is inside the try but the success `conn.send` is after it; the review identifies lost serialization causality.

Root cause: transport serialization was excluded from the worker error contract.

1. Put success serialization/send inside the protected boundary.
2. Emit a bounded, serializable error envelope naming the phase; deterministically handle a second send failure.
3. Close child and pipe on every path and test unpicklable values.

**AC1:** picklable success is unchanged. **AC2:** lambda/open-handle result yields a named serialization error. **AC3:** child and pipe close deterministically without hanging. Verification: `python -B -m unittest test_aep_orchestrator`; real wrapper callbacks returning lambda and open handle. Dependencies: none.

## Defect evidence

When a runtime lacks `describe_runtime`, the fallback constructs `{runtime_config_base}`. Because `runtime_config_base` is a dict, this is an invalid set member and deterministically raises `TypeError: unhashable type: 'dict'`. The exact head source and [unresolved Critical review](https://github.com/mattmre/CHELATEDAI/pull/257#discussion_r3367630939) were opened. The PR still advertises live progress and BHS 82; lint is failing and Python 3.9 is cancelled.

Reproduce/inspect: `git show 663be66:antigravity_engine.py`; instantiate the production engine with a runtime double that intentionally omits `describe_runtime`.

Copy-paste inspection:

```powershell

gh api repos/mattmre/CHELATEDAI/pulls/comments/3367630939 --jq '[.path,.line,.body]'
```

Expected current evidence: the fallback expression is `{runtime_config_base}` and the opened review identifies the resulting unhashable-dict TypeError.

## Root cause and atomic repair

Braces converted a direct dict assignment into set construction, and coverage exercised only the richer runtime branch.

1. Assign `runtime_config_base` directly in the fallback.
2. Add a regression that crosses the real constructor boundary with a runtime lacking `describe_runtime`.
3. Prove diagnostics and model-scope defaults survive the fallback; run canonical smoke at the immutable candidate SHA.

## Acceptance criteria

- **AC1:** fallback returns a dictionary and never constructs a set.
- **AC2:** model-scope defaults are populated when `describe_runtime` is absent.
- **AC3:** real engine initialization completes without TypeError and persists the expected diagnostic state.

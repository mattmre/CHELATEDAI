## Defect evidence

The code checks `destination.exists()` and later calls `staging.replace(destination)`. That interval is a race; on platforms where replace overwrites an intervening target, the documented absent-target/fail-closed publication contract is false. Tests do not create a destination between precheck and rename.

Copy-paste inspection:

```powershell
$wt='D:\GITHUB\CHELATEDAI-RHPC1'
rg -n "destination\.exists|staging\.replace|publish_stage_a_artifact" "$wt\rhpc\artifacts.py" "$wt\tests\test_rhpc_stage_a.py"
Push-Location $wt
try { python -m unittest tests.test_rhpc_stage_a -q } finally { Pop-Location }
```

Expected current evidence: precheck is line 274 and replace is line 309; the corrected worktree-scoped command reports `Ran 15 tests` and `OK` without an intervening-target/concurrent-publisher case.

Root cause: atomic replacement was mistaken for atomic no-replace creation.

1. Use a supported atomic no-replace primitive (for example Linux `renameat2(RENAME_NOREPLACE)` or equivalent Windows semantics).
2. Fail closed when no trustworthy primitive is available; do not emulate with check-then-replace.
3. Add a competing-publisher/intervening-target disprove test and verify directory durability.

**AC1:** a target created after staging is never overwritten. **AC2:** exactly one concurrent publisher succeeds. **AC3:** failure removes only its own staging directory and preserves the winner. Verification: multiprocess hostile race on each supported OS plus artifact verifier. Dependencies: WT020-002/003 boundary-hardening slice.

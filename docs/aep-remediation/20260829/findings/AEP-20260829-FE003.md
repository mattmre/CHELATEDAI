## Defect evidence

Artifact-derived reason, node ID, outcome, sweep config, feature values, recommendation, and candidate name enter `innerHTML`. Backend loaders accept general JSON without a closed field schema. Local binding reduces reach but does not make checkout/artifact text trusted, and token-protected non-loopback mode is explicitly supported.

Copy-paste inspection:

```powershell
rg -n "innerHTML|nodeid|candidate_name|recommendation|reason" dashboard/index.html dashboard_server.py
rg -n "json\.load|handle_api_sweep_results|handle_api_test_results" dashboard_server.py
```

Expected current evidence: artifact fields are interpolated into `innerHTML` in both external and inline clients; loaders accept JSON without a closed rendering schema.

Root cause: data and markup share template strings in two independently maintained clients. Status is blocked until the dashboard slice owns a real browser harness; source inspection proves the sink but cannot substitute for the required hostile-artifact browser acceptance.

1. Replace data-bearing templates with `createElement`/`textContent` in external and fallback clients.
2. Validate response fields and bounds at the API/client boundary; reject unsupported schema versions.
3. Add browser tests using hostile persistent artifact strings in every sink.

**AC1:** hostile text renders literally and never creates nodes/handlers. **AC2:** both clients share the safe behavior. **AC3:** valid artifacts retain content and layout. Verification: serve controlled hostile JSON, run real browser assertions, and scan for remaining data-bearing `innerHTML`. Dependencies: both clients must change atomically; do not solve with a wholesale dashboard rewrite (L16 risk).

## Defect evidence

The two tests set `max_wall_seconds=0.05`, perform multiple real writes/verifications/fsyncs before promotion, then unconditionally assert that the target directory exists. A deterministic production-path probe expires the legitimate `parent fsync immediately before promotion` checkpoint and proves `target_is_dir=False`, so the tests' postcondition is invalid whenever the whole-run deadline expires before their mocked delayed stage. Twenty isolated two-test runs pass and the quiet 3,633-test rerun passes; the earlier unsealed suite failure is retained only as diagnostic context. The replayable stage probe—not the missing raw stream—is the controlling defect evidence.

## Root cause and atomic repair

The tests use absolute wall-clock exhaustion to select an internal lifecycle stage. Under suite load, the deadline can expire earlier, so the test no longer exercises its named path.

1. Inject a deterministic monotonic clock/deadline controller or stage hook into the smoke lifecycle.
2. Advance it specifically during promotion or receipt preparation; assert the hook was reached before checking artifact state.
3. Retain a separate bounded real-clock smoke with a generous platform margin, but do not use it for stage selection.

## Acceptance criteria

- **AC1:** each test deterministically reaches its named delayed stage on loaded and idle hosts.
- **AC2:** promotion case leaves the intended uncommitted directory and receipt-preparation case leaves no public/prepared receipt.
- **AC3:** repeated full-suite runs do not vary while production deadline refusal remains fail-closed.

## Defect evidence

A correct status-checking `fetchJson` exists, but Test, Summary, Events, Sweep, and BEIR loaders bypass it, parse error JSON, then coerce absent keys to zero/empty arrays. Real 401/404/500 states can appear as “No events/results” or numeric zero.

Copy-paste inspection:

```powershell
rg -n "fetchJson|await fetch\(|\.json\(\)|\|\| 0|No events|No results" dashboard/index.html
rg -n "send_error_response\(401|send_error_response\(404|send_error_response\(500" dashboard_server.py
```

Expected current evidence: multiple loaders use raw fetch/json instead of `fetchJson`; error handlers return JSON envelopes that those loaders can coerce into success-shaped empties.

Root cause: duplicated raw fetch/parse paths and no discriminated success/error contract.

1. Route all loaders through one status-aware client and a versioned envelope.
2. Render loading, valid-empty, unavailable, unauthorized, invalid, and stale as distinct states.
3. Add browser tests for representative 401/404/500/malformed responses and last-good stale labeling.

**AC1:** non-2xx never enters success rendering. **AC2:** valid zero remains distinguishable from unavailable. **AC3:** errors carry status/context without leaking server internals. Verification: ephemeral server response matrix plus DOM assertions. Dependencies: implement after/with FE001 auth and FE002 report contracts.

## Defect evidence and commands

`_decode_canonical(result_path)` reads, parses, and canonicality-checks one byte sequence. The caller then executes `result_path.read_bytes()` again for size and SHA binding. Replacement between those reads makes the regenerated/validated mapping differ from the bytes recorded in the artifact.

## Root cause and atomic fix steps

The decoder returns only the mapping, discarding the exact bytes it validated, so downstream binding must reopen the mutable path.

1. Open/snapshot the regular single-link result once and return both canonical bytes and decoded mapping.
2. Derive canonicality, size, SHA, semantic digest, and regeneration comparison from that same byte object.
3. Retain existing link/reparse/ancestry checks and ensure the open/snapshot boundary cannot silently follow a replacement.
4. Add a deterministic replacement-on-second-open fixture; after repair, the implementation should perform no second path read.

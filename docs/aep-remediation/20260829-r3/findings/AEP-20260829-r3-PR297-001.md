## Defect evidence and commands

Claim IDs are loaded directly into associative arrays, so a later row replaces the earlier claim without an error. Work IDs are appended and counted without a seen-ID check, so a repeated work increases both `related_works_total` and, when strong, `related_works_strong`. The PR describes the script as a deterministic validator, but it accepts both duplicate primary keys with exit code zero.

The exact-head baseline produced:

```text
METRIC claim_coverage=100.0
METRIC related_works_total=88
METRIC related_works_strong=77
METRIC structural_duplicates_considered=4
```

A disposable exact-head copy was then given one second `c01` claim row with conflicting content and one second strong `w01` work row. Running the unmodified `autoresearch.sh` produced:

```text
METRIC claim_coverage=100.0
METRIC related_works_total=89
METRIC related_works_strong=78
METRIC structural_duplicates_considered=4
exit_code=0
```

$i=0

Expected output shows associative assignments at 26-27, unconditional work counting at 39, and unconditional append at 64, with no duplicate-ID branch.

## Root cause and atomic fix steps

The parser treats TSV IDs as collection labels, not schema primary keys.

1. Maintain explicit `SEEN_CLAIM_IDS` and `SEEN_WORK_IDS` associative sets with source row numbers.
2. Reject a duplicate before mutating claim maps or incrementing any metric, reporting the repeated ID and both row numbers.
3. Validate the header and exact column count so identity checks cannot be bypassed by shifted fields.
4. Add positive baseline and duplicate-claim/duplicate-work fixtures; keep the current baseline metrics unchanged.

## Acceptance criteria

- **AC1:** duplicate claim and work IDs each terminate nonzero with the repeated ID and original/duplicate row numbers.
- **AC2:** no duplicate row can replace claim text or inflate total/strong/category metrics.
- **AC3:** the unmodified exact-head catalog still reports `100.0`, `88`, `77`, and `4`, and malformed identity fixtures are part of the normal script test gate.

Verification commands: run `bash autoresearch.sh` on the tracked catalog; run the two duplicate fixtures and assert nonzero status plus exact diagnostics; run ShellCheck if available. Dependencies: none beyond choosing the canonical TSV header/row-number diagnostic format.

## Defect evidence and commands

`run_supervised` stores observation, stop, child, and restoration errors in one mutable `failure` slot. `child_failure` preserves a child exception, but there is no equivalent primary slot for an `observe_before` failure. When `restore_and_verify` also fails, the restoration exception overwrites the observation exception and is raised with neither cause nor context.

## Root cause and atomic fix steps

The supervisor models multiple independent failures as a single replaceable value.

1. Track the primary execution failure and restoration failure separately, including stage and service-state metadata.
2. Construct one typed aggregate/multi-error that preserves both errors and their causal order; never replace the primary error with cleanup text.
3. Write the same structured chain to a durable private recovery receipt before returning; avoid creating an empty quarantine directory as the only artifact.
4. Add deterministic dual-failure regressions for observation+restoration, child+restoration, and partial-stop+restoration paths.

## Acceptance criteria

- **AC1:** a dual failure exposes both `PRIMARY_OBSERVE_FAILURE` and `SECONDARY_RESTORE_FAILURE` in a stable typed chain or aggregate.
- **AC2:** no result is published, quarantine remains explicit, and the terminal service state is recorded even when restoration fails.
- **AC3:** deterministic regressions cover all three primary-stage pairings and fail if cleanup overwrites primary causality.

## Defect evidence and commands

`write_pool_shard` writes the fixed payload path first and the adjacent manifest second. `_read_pool_shard_with_manifest` reads the manifest and payload but never checks `manifest["vector_sha256"]` against the decoded payload before returning vectors with manifest-owned `doc_ids`. If the second write fails during replacement, a normal reader accepts the new payload under the old IDs whenever the shape remains compatible.

## Root cause and atomic fix steps

The two-file format has no generation commit point, and ordinary reads do not authenticate payload bytes against the manifest.

1. Write payload and manifest to unique same-directory temporary paths, flush/close them, and never expose either partial file as a completed generation.
2. Make the manifest or a separate pointer the commit record for an immutable/versioned payload, or use one atomic container; retain prior generation until the commit record is replaced.
3. On every public read, recompute the decoded vector SHA and reject unless it matches the manifest before pairing vectors with `doc_ids`.
4. Add deterministic failure injection after payload preparation, during commit-record replacement, and during overwrite; add a reader/rewrite interleaving regression.

## Acceptance criteria

- **AC1:** no public read can return payload bytes from one generation with IDs or shape metadata from another.
- **AC2:** an interrupted rewrite leaves either the prior complete generation readable or an explicit fail-closed result; it never silently accepts a mixed pair.
- **AC3:** the exact failure-injection probe and concurrent reader/rewrite regression pass alongside byte-exact, NaN-payload, multi-block, and parity tests.

Verification commands: rerun the exact probe with the post-fix expected result defined by AC2; run `python -B -m unittest test_pool_shard_parity -v`; run Ruff on the changed module/test. Dependencies: preserve the experimental API warning and decide whether compatibility requires a manifest commit pointer or permits a single-container format.

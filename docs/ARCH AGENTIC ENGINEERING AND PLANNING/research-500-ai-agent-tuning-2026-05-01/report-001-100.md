# Report 001-100: AI Model And Agent Tuning Research

Date: 2026-05-01

## Executive Read

The first 100 analyzed sources strongly support ChelatedAI's current direction: keep Engine-Scope and Model-Scope separate, build reversible steering and promotion surfaces first, and make evaluator/comparator discipline the center of the self-improvement loop.

The highest-value finding is not a single model-tuning algorithm. It is a stack pattern:

1. Capture internal or engine-side features.
2. Route decisions through fail-closed gates.
3. Spend test-time compute selectively.
4. Use multiple verifiers/evaluators before promotion.
5. Store only typed, replayable memory.
6. Train overlays or policies from curated traces, not from raw self-generated enthusiasm.

## Key Findings

### 1. Self-improvement must be comparator-first

Reflexion, Self-Refine, SELF, DSPy, TextGrad, STaR, and process-supervision work all point in the same direction: autonomous improvement only works when feedback is structured and measured. Raw reflection is too prone to reinforcing bad lessons.

ChelatedAI implication: `expectation_comparator.py`, `run_model_scope_campaign.py`, and replay bundles should become the authority for persistence. Reflection or self-generated feedback should be treated as candidate data, not truth.

### 2. Test-time compute is a real control surface

Tree of Thoughts, Graph of Thoughts, Self-Consistency, Large Language Monkeys, AlphaCode-style sampling, and test-time compute papers support a controlled search layer. The key is budget allocation: spend branches only where uncertainty, verifier disagreement, or task hardness justifies it.

ChelatedAI implication: add a compute-budget scheduler that decides between direct answer, self-refine, best-of-N, branch search, or multi-verifier escalation.

### 3. Retrieval needs adaptive gates, not global knobs

HyDE, Query2doc, Self-RAG, Corrective RAG, FLARE, RAPTOR, ColBERTv2, SPLADE, RankGPT, and RAGAS all argue against a one-size retrieval policy. Query expansion, reranking, and corrective retrieval should activate conditionally.

ChelatedAI implication: extend `learned_reformulation_gate.py` and `learned_mask_gate.py` into a broader `retrieval_policy_gate` trained from Engine-Scope rows.

### 4. Preference optimization should be overlay-level first

DPO, KTO, ORPO, IPO, SimPO, SLiC-HF, and RLAIF are useful, but they should not drive base-weight mutation in the first model-scope implementation. They fit better as LoRA/probe/adapter training options behind replay gates.

ChelatedAI implication: `model_scope_trainer.py` should support preference-loss families as interchangeable objectives for reversible artifacts.

### 5. Evaluators are infrastructure, not extras

G-Eval, Prometheus, Prometheus 2, MT-Bench, process reward models, verifier papers, RAGAS, and SWE-bench all reinforce that the system needs explicit evaluator layers. The evaluator itself must be calibrated and checked for drift.

ChelatedAI implication: add evaluator provenance, evaluator agreement metrics, and evaluator-family diversity to campaign reports.

### 6. Tool and model routing are near-term wins

Toolformer, Gorilla, MRKL, RouteLLM, FrugalGPT, AutoGen, Anthropic's effective-agent patterns, and dynamic tool retrieval work all map cleanly to learned routing and role orchestration.

ChelatedAI implication: add explicit model/tool route decisions as first-class Engine-Scope rows, then train fail-closed route gates.

## Expert Panel Critique

### Architecture Lens

The repo's split between Engine-Scope and Model-Scope is validated. The missing piece is a shared evidence contract: every gate, route, steering action, and memory promotion needs a common episode schema so results are comparable across layers.

### ML Systems Lens

The strongest near-term opportunities are not heavier model training. They are better data generation and evaluation loops: hard-negative mining, branch search, verifier disagreement sampling, and typed replay bundles.

### Safety Lens

Activation steering and autonomous reflection are both high-risk if allowed to persist without regression checks. The source set supports steering, but also shows it can degrade safeguards. Every steering feature needs a safety counterpart: provenance, off switch, rollback, and adversarial replay.

### Product/Velocity Lens

The best 1-2 day additions should sit on top of existing campaign infrastructure: evaluator agreement, adaptive compute budget, route telemetry, and hard-negative generation. These are easier to land than full model-scope sparse-feature integration and will improve later model-scope work.

## Explosive Realignment Potential

The largest realignment opportunity is to treat ChelatedAI as an evidence-driven adaptive control system rather than a collection of tuning scripts.

That means turning each run into:

1. an episode trace,
2. a feature footprint,
3. a route/action decision record,
4. an evaluator panel result,
5. a replayable promotion candidate,
6. and a rollback-safe artifact.

If this becomes the organizing contract, Engine-Scope gates, Model-Scope sparse features, retrieval tuning, tool routing, and preference overlays can all use one promotion language. That is the shortest path to coherent self-improvement without unsafe autonomous drift.

# Report 101-200: Model Internals, Sparse Steering, Retrieval, Memory, And Evaluation

Date: 2026-05-01

## Executive Read

The second 100 analyzed sources sharpen the architecture boundary. Sparse features, activation steering, Qwen-Scope-style adapters, and mechanistic tooling are high-upside, but the literature is full of warnings: circuits often do not scale cleanly, features can be fragile, model edits can accumulate catastrophic forgetting, and steering can bypass or weaken safety behavior.

The practical conclusion is clear: build the hook bus and feature layer, but treat every intervention as a reversible, logged, shadow-mode candidate until replay, red-team, and comparator evidence say otherwise.

## Key Findings

### 1. Hook-bus correctness should be tested on known mechanistic tasks

IOI, induction heads, TransformerLens patching APIs, causal scrubbing, and ACDC give concrete fixtures for validating hook capture, clean/corrupt activation patching, and causal claims.

ChelatedAI implication: `model_hook_bus.py` should not only have schema tests. It should include at least one tiny-model causal patching fixture so the bus proves it can reproduce a known intervention.

### 2. SAE features are useful only with feature-quality scorecards

Monosemanticity, SAE scaling work, Gemma Scope, GPT-2 SAE releases, and Qwen-Scope model cards all support feature interfaces. But reconstruction loss, feature splitting, feature polysemanticity, and steering fragility mean "feature exists" is not enough.

ChelatedAI implication: `model_scope_features.py` needs a feature scorecard: activation frequency, reconstruction residual, label confidence, intervention sensitivity, collision risk, and replay impact.

### 3. Qwen-Scope should start with cheap smoke tests, then scale

The Qwen-Scope model cards provide the most direct path for the planned Model-Scope layer. The safer order is small Qwen SAE smoke test, then Qwen3-8B, then Qwen3.5-9B. Expensive MoE variants should remain design-compatible but deferred.

ChelatedAI implication: start with `Qwen3.5-2B` or similarly cheap SAE-compatible target for hook/feature validation before treating `Qwen3.5-9B` as the serious benchmark.

### 4. Base model editing is the wrong near-term target

ROME, MEMIT, SERAC, MEND, and catastrophic-forgetting evidence all argue that persistent edits require a much stronger safety framework than the repo currently has. SERAC-like external edit memory is much better aligned with the current reversible-artifact posture.

ChelatedAI implication: keep the base-weight mutation prohibition. Promote external overlays, probes, edit memories, or LoRA adapters only.

### 5. Retrieval evaluation needs faithfulness, not just correctness

ARES, RAGTruth, RAGBench, RAGChecker, attribution-bias work, ClashEval, and faithfulness studies show that correct answers can still cite wrong evidence or ignore retrieved context. Retrieval metrics must separate answer correctness, context relevance, groundedness, attribution faithfulness, and conflict resolution.

ChelatedAI implication: campaign reports should add a retrieval faithfulness matrix instead of one aggregate RAG score.

### 6. Memory should be an evidence store, not a loose context dump

MemGPT, MemoryBank, GraphRAG, LightRAG, HippoRAG, KAG, RETRO, and kNN-LM all reinforce typed memory and retrieval structures. The best fit for this repo is not unlimited conversation memory; it is replayable evidence memory with retention, freshness, and provenance.

ChelatedAI implication: `model_scope_memory.py` should persist episode bundles, promoted artifacts, feature labels, evaluator judgments, and replay families with explicit retention policies.

### 7. Production observability can become the replay substrate

OpenTelemetry GenAI conventions, OpenInference/Phoenix, LangSmith, and TruLens show the field converging on model/tool/retrieval trace schemas. ChelatedAI should not lock into a vendor, but it should emit trace-shaped events so evidence can be inspected and replayed.

ChelatedAI implication: define internal traces with an OpenTelemetry-compatible export path.

## Expert Panel Critique

### Mechanistic Interpretability Lens

Do not confuse interpretability affordances with control guarantees. A feature can be human-interpretable yet unsafe or unreliable as an actuator. The system needs causal tests and replay deltas before any feature can steer behavior.

### ML Safety Lens

The negative results are as important as the positive ones. The Hydra Effect, jailbreak papers, model-editing forgetting, and SAE fragility should become explicit regression families.

### Retrieval Systems Lens

Current retrieval work should shift from "did retrieval help?" to "which retrieval intervention helped, why, and under which evidence conflict?" This maps directly to Engine-Scope row emission.

### Infrastructure Lens

Trace-shaped evidence is the natural spine of this architecture. If every action has span-like metadata, replay, observability, evaluation, and promotion all become simpler.

## Explosive Realignment Potential

The new high-leverage alignment is a single trace-backed evidence model across Engine-Scope and Model-Scope:

1. Engine-Scope rows capture retrieval decisions, route decisions, and intervention candidates.
2. Model-Scope events capture hooks, features, probes, and steering deltas.
3. Evaluator spans capture correctness, faithfulness, safety, uncertainty, and reviewer agreement.
4. Replay bundles bind all three into a promotion candidate.

This would let ChelatedAI compare retrieval policies, steering overlays, memory choices, and model routes under one evidence contract.

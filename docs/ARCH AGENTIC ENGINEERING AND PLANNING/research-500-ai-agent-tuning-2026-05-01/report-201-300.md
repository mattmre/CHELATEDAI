# Report 201-300: Preference Optimization, Evaluators, Production Agent Loops

Date: 2026-05-01

## Executive Read

The third 100 analyzed sources shift the center of gravity from "which tuning loss should we use?" to "how do we keep any tuning or agent loop from optimizing the wrong thing?" Reward-model overoptimization, judge bias, preference-data weakness, and production-agent trace failures all point to the same discipline: every optimization loop needs heldout evaluators, trace-level grading, and explicit stop conditions.

The new repo-level conclusion: ChelatedAI should build a durable eval-and-trace substrate before adding aggressive continual preference tuning.

## Key Findings

### 1. Preference tuning should be pluggable and evidence-gated

DPO, KTO, ORPO, SimPO, IPO, Nash learning, contrastive variants, online DPO, and self-play optimization all offer useful objectives. None should become the canonical path before the repo can compare them under the same replay set.

ChelatedAI implication: `model_scope_trainer.py` should expose a preference-objective interface, but promotion should be blocked by replay, evaluator agreement, and reward-overoptimization checks.

### 2. Reward models need overoptimization guardrails

Reward-model scaling and uncertainty-aware RLHF show that optimizing a proxy too hard creates collapse. This maps directly to the repo's autopilot loops: a candidate can improve the judging metric while degrading actual task performance.

ChelatedAI implication: every reward/evaluator-backed campaign should track heldout evaluator deltas, uncertainty, and disagreement. Stop optimization when heldout reward diverges from training reward.

### 3. Process supervision is a better fit than outcome-only scoring for agentic work

PRM800K, process/outcome feedback, and generative verifiers show why multi-step tasks need step-level feedback. Outcome-only success hides brittle reasoning, tool misuse, and unsupported claims.

ChelatedAI implication: add optional step spans and process-score fields to episode traces. Process labels can begin as evaluator-generated and later be human-calibrated.

### 4. Trace-level grading is the production form of self-improvement

AgentOps, OpenAI trace grading, AgentEvals, LangSmith trajectory evals, and LangGraph durable execution all converge on trajectory-level evidence. Good agent systems grade what happened, not only the final text.

ChelatedAI implication: campaign replay should grade sequences of tool calls, model calls, retrieval actions, evaluator decisions, and final outcomes.

### 5. Test-time compute should include plan/no-plan and debate/no-debate gates

Agentic TTS, Learning When to Plan, debate-as-scaling, Large Language Monkeys, and AFlow show that not every task deserves deeper orchestration. The scheduler needs conditional escalation.

ChelatedAI implication: add a cheap classifier or policy that chooses direct answer, plan, refine, branch, debate, multi-agent, or stop.

### 6. Agent safety requires interactive benchmarks and monitors

AgentHarm, Agent-SafetyBench, SafeAgentBench, R-Judge, weak-to-strong monitoring, SafetyFlow, and honeypot work show that static text safety tests are not enough for tool-using agents.

ChelatedAI implication: `run_safety_testbed.py` should include action-sequence safety checks and monitor outputs, not only prompt/response classification.

## Expert Panel Critique

### Alignment Lens

Preference objectives are not interchangeable commodities. They encode different assumptions about feedback shape, reward margin, reference models, and uncertainty. ChelatedAI should treat them as experiment modes under one promotion gate, not as a permanent commitment.

### Evaluation Lens

The highest priority is evaluator calibration. A local evaluator model is valuable only if it is tested against private holdouts, randomized pair order, length controls, and disagreement sampling.

### Agent Runtime Lens

Durable execution is not optional for long-running autopilot work. Checkpoints, resumable state, tool-call traces, and idempotent replay are the difference between research automation and opaque batch scripts.

### Safety Lens

Agent safety must inspect actions. Tool calls, file writes, retrieval choices, and hidden intermediate decisions can be unsafe even when the final answer looks acceptable.

## Explosive Realignment Potential

The strongest realignment after 300 sources is to convert `run_*_campaign.py` from batch scripts into durable, trace-graded experiment runners:

1. Every campaign emits trace spans.
2. Every trace has final and process-level evaluator scores.
3. Every preference pair or training example links back to trace evidence.
4. Every candidate overlay is trained from replayable evidence.
5. Every promotion is blocked if reward gains diverge from heldout evaluator outcomes.

This creates a clean path from agent telemetry to training data without letting the system blindly optimize its own noise.

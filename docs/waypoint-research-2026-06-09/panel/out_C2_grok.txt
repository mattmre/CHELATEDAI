## Attack results

### 1. Circularity — **not disproven as fake LOO**
`leave_one_regime_out` trains only on the other regimes (`validation.py:63–83`). Feature mean/scale are fold-local (`calibration.py:90–107`). Features are pack-local (`features.py:152–262`). Held-out `R` does not enter its own prediction. Rebuilt LOO from feature JSONs matches the artifact.

### 2. Trivial-predictor confound — **lands hard**

| Predictor (LOO) | Spearman | MAE | Bin acc |
|---|---:|---:|---:|
| **Shipped multi-feature R̂ (α=10)** | **−0.40** | 0.079 | 0.75 |
| Mean train R | −1.00 | 0.085 | 0.50 |
| Floor NDCG → R | 0.00 | 0.124 | **0.75** |
| Oracle gap → R | **+0.60** | **0.072** | — |
| Constant 0.7 | n/a | **0.064** | 0.50 |
| **OLS `oracle_margin_mean` alone** | **+1.00** | **0.033** | — |

Shipped R̂ is **worse on rank than oracle-gap alone**, and **worse on MAE than a constant**. Bin accuracy 75% equals floor-only LOO. Report never states this → incomplete negative.

### 3. Regime count honesty — **OK**
4 real packs (SciFact/NFCorpus × mpnet/bge), offline-built, SHA in manifest, models recorded. Not fabricated. `≥3` bar met; **VALIDATION-NEGATIVE** (not SCOPING-NEGATIVE) is the right label for the locked rule.

n=4 Spearman is still nearly noise (one swap flips sign). Report should say “failed locked bar on n=4 underpowered correlation,” not imply a high-power kill. Mild over-claim risk, not a FAIL.

### 4. Leakage — **ridge path clean**
`leakage_safe_fit_indices` rejects eval-positive docs (`features.py:45–68`). Ridge never receives qrels (`features.py:106–126`). SciFact locked label R=0.8434 is the leaky D1 waypoint while features use safe fit (R_safe=0.7891) — **disclosed** in `estimator_validation.md`. Label/feature mismatch hurts that regime; it is not validation circularity. Using R_safe labels still yields LOO Spearman −0.40.

### 5. Margin-bound correctness — **formula OK; tests thin**
Implemented as stated:  
`slack = m − ‖q‖(‖e_r‖ + ‖e_j‖)` (`margin_bound.py:47–84`).  
Hand arithmetic `0.6 − 1·(0.1+0.2) = 0.3` is correct. Synthetic pack margin `0.4` is hand-checkable. End-to-end slack on the tiny pack is consistent (manual = extracted = −0.0297 → inversion).  
**Gap:** synthetic test never asserts error norms / slack / inversion (`test_estimator.py:102–112` only checks margin=0.4). Not tautological, but incomplete.

After row-normalize, `‖q‖ ≡ 1`. With `‖e‖ ~ 0.4–0.5`, RHS ≫ typical margins (~0–0.08) → **100% violation is expected**, not surprising.

### 6. Positive-or-negative framing — **negative is directionally honest; root cause is incomplete (Attack B)**

Codex focus: binary inversion rate saturates at 100% everywhere. True.

What they under-sold:

| Feature | Univariate Spearman vs R | Notes |
|---|---:|---|
| `predicted_inversion_rate` | constant 1.0 | dead |
| `oracle_margin_mean` | **+1.0** | **extracted, not in FEATURE_NAMES** |
| `oracle_margin_q50` | +0.8 | in FEATURE_NAMES |
| `oracle_margin_sign_rate` | +0.8 | in FEATURE_NAMES |
| OLS LOO `margin_mean` | **+1.0**, MAE 0.033 | would clear Spearman ≥ 0.7 bar on this n=4 set |
| Full FEATURE_NAMES α=10 LOO | −0.40 | shipped |
| Full FEATURE_NAMES α=0.01 LOO | 0.00 | multi-feature still fails at n=3 |

So: **wrong-feature (binary rate) is dead; continuous margin is not.**  
The shipped map fails because (i) the primary advertised feature is constant, (ii) `oracle_margin_mean` is never calibrated (`calibration.py:13–22`), (iii) α=10 with 8 features and 3 train points shrinks toward the mean and scrambles rank. Framing “core signal saturated” as the whole story is incomplete.

## Attack results

### 1. Real block-graph traversal vs shortcut — **NOT FAKED**

`_decode_payload_via_block_graph` (`pool_shard.py:138–192`):

- Loads payload as opaque bytes
- Calls `read_block(payload, offset)` per block
- Validates each cell as finite integer in `[0, 255]`
- Checks `next_offset` against the expected linear chain and **sets** `offset = block.next_offset`
- Crops to `raw_vector_bytes`, rejects non-zero padding

Instrumented multi-block read (`n=200, d=400` → 2 blocks): `read_block` called at offsets `[0, 524296]`. No `np.load` / mmap / raw array reload.

Direct `build_graph_payload` of float32 values is lossy (`0.1` → `0.09997…`); the same values survive the byte-lane path bit-exactly. So the encoding is load-bearing, not decorative.

### 4. Manifest integrity — **HOLDS for stated contract**

`verify` hashes **disk-read** logical bytes and requires:

`manifest_sha256 == disk_sha256 == in_memory_sha256` **and** ids **and** `array_equal`.

| Attack | Outcome |
|---|---|
| Edit manifest hash to zeros | `manifest_hash_match=False` |
| Corrupt disk, forge manifest to new disk hash | still fails `in_memory_hash_match` |
| Corrupt disk, keep original manifest hash | fails (disk ≠ host) |
| Id count ≠ shape[0] | `ValueError` on read |

Note (non-blocking): a sidecar manifest can re-label the **same raw bytes** under a different shape with the same byte count if the caller’s host is also re-shaped to match. That is host collusion / trust of manifest metadata, not a parity bypass of vector bits. Manifest is not a full authenticated package over shape+ids+payload; parity is three-way vs a known host.
